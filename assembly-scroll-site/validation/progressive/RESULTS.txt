Delivered locally. No push, deployment or production format change.

Implemented
- Useful-resolution opening, a 600 ms conservative fallback, paused refinement.
- Separate desired, streaming and displayed quality, with measured recovery and cooldowns.
- Foreground-first scheduling, one speculative job within four total jobs.
- Twelve decoded bitmaps / 48 MiB including decode reservations, plus a separate 24 MiB compressed cache.
- Active-orientation lookahead and qualified full preparation, with no repeated speculative attempts.
- Speculation and chapter warming yield under delivery pressure until a 600 ms pause.
- Data Saver, optional stills, reduced motion, Retry and connector inspection remain available.
- Both orientations, 421 positions, 12 viewport heights and 100 ms easing are preserved.

REGRESSIONS AND INVESTIGATION

Normal-phone cold startup increased from 54.5 ms to 66.1 ms, about 12 ms, while the
opening changed from 540p to 1080p. The absolute change is below one 60 Hz refresh.
First-frame speculation is disabled until a valid canvas frame exists, so speculative
downloads cannot account for the initial canvas delay. Short-run scheduling variation
and the sharper decode/draw remain part of this measurement. No universal startup gain is claimed.

The final local slow warm run increased from 196 ms to 363 ms. This raw regression is
retained, not removed from the summary. The Python preview server supplies Last-Modified
but no explicit Cache-Control, while the deployed Pages response has max-age=600.
Recently edited modules can therefore revalidate differently from the older baseline.
This is a likely explanation, not a directly observed revalidation trace from those runs.

A separate 15-pair controlled warm-reload investigation used the same server and explicit
HTTP caching for both revisions. JavaScript transfer sizes were zero, and both still fetched
the manifest. Under slow network / 4x CPU, baseline median was 416 ms and new code 410 ms.
The normal-network warm comparison was 40 ms versus 36 ms. This does not reproduce a
runtime startup slowdown, but it uses a different reload protocol and does not replace
the primary results. No performance claim is made for a newly deployed release.

The first implementation also rejected cached sharp images using skipped timeline
positions as decode demand. Capping demand at 60 displayed frames per second raised
fast-phone sharp-pose coverage from about 10 percent to above 90 percent and reduced
redundant lower-tier transfer. Guards still require 30 percent decoding headroom.

FORMAT COMPARISON

120 browser cases passed: 60 orientation/resolution/format combinations at normal and
constrained networking, with forward/reverse seeking and exact stopping checks.
240 source-pixel samples and a labeled contact sheet supplement the timing results.
AVIF 65 saves about 30 percent at 1080p relative to current WebP. H.264 GOP6 is smaller
but had slower random seeking on the constrained connection. Keep production WebP pending
broader device format validation. Details are in FORMAT-COMPARISON.txt and formats.json.
