Behavior
The stage follows the visible viewport, while small viewport units keep
scroll distance stable during browser toolbar changes. Rotation receives
a settled geometry check. Pinch zoom remains available.

Phones start at 720p, or 540p when data-saving or constrained-network
information is available. Measured image delivery time and scroll speed
can shorten the quality reduction delay from 800 ms to 350 ms. Slow
delivery never automatically changes the site to chapter stills.

Loading feedback stays quiet while images advance. It appears after a
600 ms stall, or an unresolved chapter tap lasting 350 ms. Actual failures
retain the current view, expose Retry and use an accessible announcement.

Navigation uses 13px text on phones. Short 15px HTML instructions replace
the small exported caption. Compact landscape places text beside the
assembly and uses more horizontal space. The original connector circles,
part labels and chip markings remain in the artwork. The first touch hint
reads Swipe up to assemble.

Each fully visible connector circle is a tap target with a plus button.
It opens an accessible dialog on the currently displayed pose, immediately
enlarges the existing image, then requests one 1080p source image through
the bounded loader. The assembly pauses during inspection. Close or Escape
returns focus and resumes at the same progress and streaming resolution.
Failures retain the immediate enlargement and offer Retry. Rotation while
the dialog is open preserves the selected connector.

The constrained profile is 1.6 Mbps download and 150 ms latency with cache
bypassed, using the real phone CPU. No CPU slowdown was applied to it.
The normal run uses the local server through USB forwarding.

For context, the earlier public-site constrained audit recorded 134
forward poses, a 693 ms maximum change gap and a 2157 ms first image.
The new initial image did not become faster in that profile. The earlier
normal audit reported loading feedback in roughly 91% of samples, and
the constrained audit about 96%. Both current profiles recorded zero
loading samples while traversing. Artificial stall and failed-image tests
separately verify that feedback and Retry still appear when appropriate.

These are not controlled before/after performance claims. The previous
audit used GitHub Pages, the current run uses a USB-forwarded local server,
and gesture duration differs. This evidence supports the functional fixes
and continued animation under constraint, not universal smoothness.

Only changes of image index count as changed poses. The raw observer also
records a redraw after toolbar geometry changes. In the slow forward run,
190 raw observations become 170 changed poses after deduplication. The
apparent 1093 ms gap was a repeated redraw of final frame 420 while already
assembled, not an animation stall. summary.json uses corrected counts.
Changed-pose counts are not display FPS or GPU frame-time measurements.

Validation notes
Two early phone layout attempts encountered stale locally cached HTML
while development assets changed. A reload with cache bypass recovered
the page. The Android layout test now uses a fresh run URL. A connector
tap issued immediately after the first canvas draw raced the initial
layout update, so that harness waits 500 ms before its first touch. The
isolated reruns passed. Runtime asset URLs are versioned together for
the next authorized publication. These interruptions are not counted as
passing checks in the final evidence.

Limits
One recent high-end Android phone and Chrome. No iPhone Safari, Firefox,
Samsung Internet, lower-end phone, TalkBack user journey, battery test or
physical cellular-radio test. The 200% text check changes CSS sizes, not
Android's global accessibility setting. The bitmap budget excludes canvas
buffers, GPU storage and total browser memory. No field Core Web Vitals
or public deployment validation was performed in this task.

Reproduction
Use README.txt and tests/android-*.cjs for phone setup and restoration.
Run browser.cjs and fallback.cjs with VALIDATION_DIR pointing here. Other
browser scripts accept VALIDATION_OUTPUT. After saving test evidence, run:

  python3 scripts/record_mobile_validation.py

That script checks the evidence, deduplicates pose changes, verifies
resource limits and protected-file scope, and fingerprints the runtime.
